## Reporting a vulnerability

If you think you've found a security problem in Ahoy, please report it privately through GitHub's form rather than opening a public issue:

[Report a vulnerability](https://github.com/ahoy-cli/ahoy/security/advisories/new)

Only the maintainers can see your report. It helps to include:

- the Ahoy version (`ahoy --version`) and your operating system
- the steps or a minimal `.ahoy.yml` that shows the problem
- what an attacker could do with it

Ahoy is maintained by volunteers, so replies are best effort. We'll confirm we've received your report, keep you updated while we work on a fix, and credit you in the advisory unless you'd rather stay anonymous. Please give us 14 days to release a fix before you share details publicly.

The full policy is in [SECURITY.md](https://github.com/ahoy-cli/ahoy/blob/master/SECURITY.md).

## Supported versions

Security fixes go into the latest v3 release. Upgrade to it before reporting, in case the problem is already fixed.

## Verifying downloads

Releases from v3.0.1 onwards include a SHA-256 checksum for every binary, and releases from v3.0.2 onwards are also signed with cosign. Older releases either have no checksums file or don't list the `ahoy-bin-*` binaries in it. See [Verifying your download](/guides/getting-started/#verifying-your-download).
