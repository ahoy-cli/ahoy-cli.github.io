# Next Steps with Ahoy

Now that you've got the basics down, let's explore some more advanced techniques and patterns that will make your Ahoy setup even more powerful and maintainable.

## Advanced Command Patterns

### Multi-line Commands

For complex operations, you can use multi-line commands with proper error handling:

```yaml
ahoyapi: v2

commands:
  full-deploy:
    usage: Complete deployment with checks
    description: |
      Runs the full deployment process with safety checks:
      - Builds the application
      - Runs tests  
      - Deploys to production
      - Sends notifications
    cmd: |
      set -e  # Exit on any error
      
      echo "🔨 Building application..."
      npm run build
      
      echo "🧪 Running tests..."
      npm test
      
      if [ $? -eq 0 ]; then
        echo "✅ Tests passed! Deploying..."
        ./deploy.sh production
        echo "🚀 Deployment complete!"
      else
        echo "❌ Tests failed. Deployment aborted."
        exit 1
      fi
```

### Interactive Commands

Create commands that prompt for user input:

```yaml
ahoyapi: v2

commands:
  create-branch:
    usage: Create a new feature branch
    cmd: |
      echo "Creating a new feature branch..."
      read -p "Enter branch name: " BRANCH_NAME
      
      if [ -z "$BRANCH_NAME" ]; then
        echo "Branch name cannot be empty"
        exit 1
      fi
      
      git checkout -b "feature/$BRANCH_NAME"
      echo "Created and switched to branch: feature/$BRANCH_NAME"
  
  safe-deploy:
    usage: Deploy with confirmation prompt
    cmd: |
      echo "⚠️  You are about to deploy to PRODUCTION"
      read -p "Are you sure? (y/N) " -n 1 -r
      echo
      
      if [[ $REPLY =~ ^[Yy]$ ]]; then
        echo "🚀 Deploying to production..."
        ./deploy.sh
      else
        echo "Deployment cancelled"
      fi
```

## Environment Variable Mastery <Badge text="v2.3.0+" variant="tip" size="small" />

### Layered Environment Configuration <Badge text="v2.5.0+" variant="note" size="small" />

Create sophisticated environment setups with multiple files:

```yaml
ahoyapi: v2

# Global environment layers
env:
  - .env.base          # Base configuration for all environments
  - .env.local         # Local development overrides  
  - .env.secrets       # Sensitive data (gitignored)

commands:
  deploy-staging:
    usage: Deploy to staging environment
    env:
      - .env.deploy      # Deployment-specific variables
      - .env.staging     # Staging environment config
    cmd: ./deploy.sh staging
    
  deploy-production:
    usage: Deploy to production environment  
    env:
      - .env.deploy      # Same deployment config
      - .env.production  # Production environment config
      - .env.prod-secrets # Production credentials
    cmd: ./deploy.sh production
```

### Environment File Examples

`.env.base`:
```bash
# Base configuration for all environments
APP_NAME=MyAwesomeApp
LOG_LEVEL=info
TIMEOUT=30
```

`.env.local`:
```bash
# Local development overrides
LOG_LEVEL=debug
DB_HOST=localhost
API_URL=http://localhost:8080
```

`.env.deploy`:
```bash
# Deployment-specific settings
DEPLOY_TIMEOUT=300
BACKUP_BEFORE_DEPLOY=true
NOTIFY_SLACK=true
```

### Dynamic Environment Selection

Create commands that work with different environments dynamically:

```yaml
ahoyapi: v2

commands:
  deploy:
    usage: Deploy to specified environment (dev|staging|prod)
    description: |
      Deploy to any environment by specifying it as the first argument.
      
      Examples:
        ahoy deploy dev
        ahoy deploy staging  
        ahoy deploy prod
        
      This will automatically load the appropriate environment file.
    cmd: |
      ENV=$1
      
      if [ -z "$ENV" ]; then
        echo "Please specify an environment: dev, staging, or prod"
        echo "Usage: ahoy deploy <environment>"
        exit 1
      fi
      
      if [ ! -f ".env.$ENV" ]; then
        echo "Environment file .env.$ENV not found!"
        echo "Available environments:"
        ls -1 .env.* | sed 's/\.env\./  /'
        exit 1
      fi
      
      echo "Deploying to $ENV environment..."
      source .env.$ENV
      ./deploy.sh $ENV
```

## Advanced Use Cases

### CI/CD Integration

Create commands specifically for continuous integration:

```yaml
ahoyapi: v2
env: .env.ci

commands:
  ci-build:
    usage: Build application for CI environment
    cmd: |
      echo "🏗️  Building for CI environment..."
      
      # Set CI-specific environment
      export NODE_ENV=test
      export CI=true
      
      # Install dependencies
      npm ci
      
      # Run linting
      npm run lint
      
      # Run tests with coverage
      npm run test:coverage
      
      # Build application
      npm run build
      
      echo "✅ CI build complete"

  ci-deploy:
    usage: Deploy from CI pipeline
    cmd: |
      if [ "$CI_BRANCH" != "main" ]; then
        echo "Deployment only allowed from main branch"
        exit 1
      fi
      
      # Deploy to staging first
      ./deploy.sh staging
      
      # Wait for staging health check
      sleep 30
      curl -f https://staging.example.com/health || exit 1
      
      # Deploy to production
      ./deploy.sh production
```

### Docker Development Workflows

Sophisticated Docker-based development commands:

```yaml
ahoyapi: v2

commands:
  dev-setup:
    usage: Complete development environment setup
    description: |
      Sets up the entire development environment including:
      - Building containers
      - Installing dependencies  
      - Setting up database
      - Running initial migrations
    cmd: |
      echo "🚀 Setting up development environment..."
      
      # Build containers
      docker-compose build
      
      # Start services
      docker-compose up -d db redis
      
      # Wait for database to be ready
      echo "Waiting for database..."
      until docker-compose exec -T db pg_isready; do
        sleep 1
      done
      
      # Install dependencies
      docker-compose run --rm app npm install
      
      # Run migrations
      docker-compose run --rm app npm run migrate
      
      # Start all services
      docker-compose up -d
      
      echo "✅ Development environment ready!"
      echo "🌐 App available at http://localhost:3000"

  fresh-start:
    usage: Reset development environment completely
    cmd: |
      echo "🧹 Cleaning up development environment..."
      
      # Stop and remove containers
      docker-compose down -v
      
      # Remove images
      docker-compose down --rmi local
      
      # Clean up volumes
      docker volume prune -f
      
      # Rebuild everything
      ahoy dev-setup
```

### Database Management

Advanced database operation commands:

```yaml
ahoyapi: v2
env: .env.db

commands:
  db-backup:
    usage: Create a timestamped database backup
    cmd: |
      TIMESTAMP=$(date +%Y%m%d_%H%M%S)
      BACKUP_FILE="backups/db_backup_$TIMESTAMP.sql"
      
      # Create backups directory if it doesn't exist
      mkdir -p backups
      
      echo "📦 Creating database backup..."
      docker-compose exec -T database pg_dump -U $DB_USER $DB_NAME > $BACKUP_FILE
      
      if [ $? -eq 0 ]; then
        echo "✅ Backup created: $BACKUP_FILE"
        
        # Keep only last 10 backups
        ls -t backups/db_backup_*.sql | tail -n +11 | xargs rm -f
        echo "🧹 Cleaned up old backups (keeping 10 most recent)"
      else
        echo "❌ Backup failed"
        exit 1
      fi

  db-restore:
    usage: Restore database from backup file
    description: |
      Restore the database from a backup file.
      
      Usage: ahoy db-restore <backup-file>
      
      Example: ahoy db-restore backups/db_backup_20240315_143022.sql
    cmd: |
      if [ -z "$1" ]; then
        echo "Please specify a backup file to restore"
        echo "Available backups:"
        ls -la backups/db_backup_*.sql 2>/dev/null || echo "  No backups found"
        exit 1
      fi
      
      if [ ! -f "$1" ]; then
        echo "Backup file $1 not found"
        exit 1
      fi
      
      echo "⚠️  This will replace the current database with $1"
      read -p "Are you sure? (y/N) " -n 1 -r
      echo
      
      if [[ $REPLY =~ ^[Yy]$ ]]; then
        echo "🔄 Restoring database from $1..."
        cat $1 | docker-compose exec -T database psql -U $DB_USER $DB_NAME
        echo "✅ Database restored successfully"
      else
        echo "Restore cancelled"
      fi
```

Create aliases that work differently based on context:


## Error Handling and Debugging

### Robust Error Handling

Build commands with proper error handling and user feedback:

```yaml
ahoyapi: v2

commands:
  deploy-with-checks:
    usage: Deploy with comprehensive error checking
    cmd: |
      # Enable strict error handling
      set -euo pipefail
      
      # Define cleanup function
      cleanup() {
        echo "🧹 Cleaning up..."
        docker-compose down
      }
      
      # Set trap for cleanup on error
      trap cleanup ERR
      
      echo "🔍 Pre-deployment checks..."
      
      # Check if required files exist
      for file in "docker-compose.yml" ".env" "deploy.sh"; do
        if [ ! -f "$file" ]; then
          echo "❌ Required file $file not found"
          exit 1
        fi
      done
      
      # Check if required environment variables are set
      for var in "DB_PASSWORD" "API_KEY"; do
        if [ -z "${!var:-}" ]; then
          echo "❌ Required environment variable $var not set"
          exit 1
        fi
      done
      
      echo "✅ Pre-deployment checks passed"
      
      # Proceed with deployment
      echo "🚀 Starting deployment..."
      ./deploy.sh
      
      echo "✅ Deployment completed successfully"

  debug-env:
    usage: Debug environment variables and configuration
    cmd: |
      echo "🔍 Environment Debug Information"
      echo "================================"
      
      echo "📁 Current directory: $(pwd)"
      echo "📋 Ahoy config file: $(ls -la .ahoy.yml)"
      echo ""
      
      echo "🌍 Environment variables:"
      env | grep -E "(DB_|API_|APP_)" | sort || echo "  No matching variables found"
      echo ""
      
      echo "🐳 Docker status:"
      docker-compose ps || echo "  Docker Compose not available"
      echo ""
      
      echo "📦 Node.js info:"
      node --version 2>/dev/null || echo "  Node.js not available"
      npm --version 2>/dev/null || echo "  npm not available"
```

## Performance and Optimization

### Parallel Command Execution

Run multiple commands concurrently for better performance:

```yaml
ahoyapi: v2

commands:
  parallel-build:
    usage: Build frontend and backend in parallel
    cmd: |
      echo "🏗️  Starting parallel build processes..."
      
      # Start background processes
      (
        echo "📦 Building frontend..."
        npm run build:frontend
        echo "✅ Frontend build complete"
      ) &
      FRONTEND_PID=$!
      
      (
        echo "⚙️  Building backend..."
        npm run build:backend  
        echo "✅ Backend build complete"
      ) &
      BACKEND_PID=$!
      
      # Wait for both to complete
      wait $FRONTEND_PID
      FRONTEND_STATUS=$?
      
      wait $BACKEND_PID
      BACKEND_STATUS=$?
      
      # Check results
      if [ $FRONTEND_STATUS -eq 0 ] && [ $BACKEND_STATUS -eq 0 ]; then
        echo "🎉 All builds completed successfully!"
      else
        echo "❌ One or more builds failed"
        exit 1
      fi
```

## Integration Examples

### Git Workflow Integration

Commands that work with your Git workflow:

```yaml
ahoyapi: v2

commands:
  feature:
    usage: Start working on a new feature
    description: |
      Creates a new feature branch and sets up the development environment.
      
      Usage: ahoy feature <feature-name>
      Example: ahoy feature user-authentication
    cmd: |
      if [ -z "$1" ]; then
        echo "Please provide a feature name"
        echo "Usage: ahoy feature <feature-name>"
        exit 1
      fi
      
      BRANCH_NAME="feature/$1"
      
      # Ensure we're on main and up to date
      git checkout main
      git pull origin main
      
      # Create and switch to feature branch
      git checkout -b $BRANCH_NAME
      
      # Start development environment
      ahoy up
      
      echo "🎉 Ready to work on feature: $1"
      echo "📝 Branch: $BRANCH_NAME"

  release:
    usage: Prepare a new release
    cmd: |
      echo "🏷️  Preparing release..."
      
      # Ensure clean working directory
      if [ -n "$(git status --porcelain)" ]; then
        echo "❌ Working directory must be clean for release"
        exit 1
      fi
      
      # Get current version
      CURRENT_VERSION=$(git describe --tags --abbrev=0)
      echo "Current version: $CURRENT_VERSION"
      
      # Prompt for new version
      read -p "Enter new version (e.g., v1.2.3): " NEW_VERSION
      
      # Run tests
      echo "🧪 Running tests..."
      ahoy test
      
      # Create release tag
      git tag -a $NEW_VERSION -m "Release $NEW_VERSION"
      
      echo "✅ Release $NEW_VERSION prepared"
      echo "📋 Next steps:"
      echo "   git push origin main"
      echo "   git push origin $NEW_VERSION"
```
