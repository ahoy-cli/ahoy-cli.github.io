## Finding your config

When you run a command, Ahoy:

1. Uses the file given with `--file` (or `-f`), if there is one
2. Otherwise looks for `.ahoy.yml` in the current directory, then in each parent directory
3. Changes to the directory that file is in
4. Runs your command from there

This means you can run `ahoy` from any subdirectory in your project and it always behaves consistently.

## Arguments

Arguments are passed to commands as bash positional parameters:

```yaml
commands:
  greet:
    cmd: echo "Hello, $1!"

  copy:
    cmd: cp $1 $2

  run-in-container:
    cmd: docker-compose exec app "$@"
```

```bash
ahoy greet World              # Hello, World!
ahoy copy src.txt dest.txt
ahoy run-in-container npm test
```

`$@` passes all arguments through, which is handy for wrapper commands. Use `$#` to check the argument count, and `$0` for the command name.

Everything after the command name reaches your command unchanged, flags included, so wrapping a tool with its own options just works:

```yaml
commands:
  phpunit:
    cmd: docker compose exec app vendor/bin/phpunit "$@"
```

```bash
ahoy phpunit --filter=MyTest --stop-on-failure
```

Ahoy's own flags, such as `--verbose` and `--file`, only count when they come before the command name, so they can't clash with your command's options.

Ahoy removes a `--` only when it comes straight after the command name. Any other `--` is passed to your command, which matters for tools that use their own separator:

```bash
ahoy k exec mypod -- ls /app       # kubectl gets its --
ahoy run npm test -- --watch       # npm passes --watch to the test script
```

## Interactive commands

Commands use the same stdin, stdout and stderr as the terminal or script that ran Ahoy. Ahoy doesn't read, buffer or copy them, so a command behaves exactly as if you'd typed it yourself:

```yaml
commands:
  shell:
    usage: Open a shell in the app container
    cmd: docker-compose exec app bash

  mysql:
    usage: Open a MySQL shell
    cmd: mysql -u$DB_USER -p$DB_PASS $DB_NAME
```

From a terminal you get a real prompt, line editing and working pipes. From a script or CI job, the command sees the same pipes or files it would see without Ahoy.

### Full-screen tools and TUI commands

Full-screen and menu tools need to ask the terminal how big it is. Because Ahoy hands over the real terminal, they get the right answer and draw properly:

```yaml
commands:
  pick-env:
    usage: Choose an environment to deploy to
    cmd: gum choose staging production

  logs:
    usage: Browse container logs interactively
    cmd: docker compose logs --tail=1000 | fzf --tac
```

This covers tools built on [Bubble Tea](https://github.com/charmbracelet/bubbletea) such as `gum` and `glow`, which draw on stderr, along with progress bars and spinners.

<Aside type="caution" title="Fixed in v3.0.1">
  Ahoy v3.0.0 sent stderr through an internal pipe. These tools then saw a 0x0 screen and drew
  nothing, and `gum` on Bubble Tea v2 crashed. If an interactive command shows a blank screen on
  v3.0.0, upgrade. See [issue #180](https://github.com/ahoy-cli/ahoy/issues/180).
</Aside>

Output is not buffered either - a long-running command's output appears as it
is produced, not in a burst when the command exits.

## Custom entrypoints

By default Ahoy runs each command with `bash -c '{{cmd}}'`. Set `entrypoint` at the top of the file to use a different interpreter:

```yaml
ahoyapi: v2

entrypoint:
  - node
  - "-e"
  - "{{cmd}}"

commands:
  hello:
    cmd: console.log("Hello from Node.js!")
```

```yaml
ahoyapi: v2

entrypoint:
  - python3
  - "-c"
  - "{{cmd}}"

commands:
  hello:
    cmd: print("Hello from Python!")
```

The entrypoint can use these placeholders:

- `{{cmd}}`: the command body
- `{{name}}`: the command name (also available as `$0`)

## Exit codes

Ahoy exits with your command's exit code, so you can chain commands in the shell:

```bash
ahoy test && ahoy deploy
```

Inside a command, the usual bash operators decide what runs next:

- `&&` runs the next command only if the previous one succeeded
- `||` runs the next command only if the previous one failed
- `;` always runs the next command

```yaml
commands:
  only-run-1-2-and-4:
    cmd: |
      echo "1 - If this passes" &&
      echo "2 - Then do this" ||
      echo "3 - Or do this if 1 or 2 fails" ;
      echo "4 - Do this no matter what"
```

## Troubleshooting

- Run with `--verbose` (before the command name) to see the exact command Ahoy ran.
- Commands run in a subshell. They get a copy of your environment, but can't change your current directory or set variables in your shell.
- Quotes can get lost when one command passes arguments to another. Check `--verbose` first, then try swapping single and double quotes. Using `cmd: |` for anything complicated keeps YAML quoting out of the way.
- If Ahoy can't read your file, run `ahoy config validate`. It reports YAML mistakes and fields Ahoy doesn't support.
