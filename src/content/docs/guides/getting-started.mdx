## Installation

<Tabs>
  <TabItem label="macOS / Linuxbrew">
    ```bash
    brew install ahoy
    ```
  </TabItem>
  <TabItem label="Linux">
    ```bash
    os=$(uname -s | tr '[:upper:]' '[:lower:]') && architecture=$(case $(uname -m) in (x86_64 | amd64) echo "amd64" ;; (aarch64 | arm64 | armv8*) echo "arm64" ;; (armv7*) echo "armv7" ;; (armv6*) echo "armv6" ;; esac) && { [ -n "$architecture" ] || { echo "Unsupported architecture: $(uname -m)" >&2; false; }; } && sudo wget -q https://github.com/ahoy-cli/ahoy/releases/latest/download/ahoy-bin-$os-$architecture -O /usr/local/bin/ahoy && sudo chown $USER /usr/local/bin/ahoy && chmod +x /usr/local/bin/ahoy
    ```

    Or download the [latest release from GitHub](https://github.com/ahoy-cli/ahoy/releases) and place the binary somewhere in your `$PATH`.

  </TabItem>
  <TabItem label="Windows (WSL2)">
    Use the Linux instructions above.
  </TabItem>
</Tabs>

<Aside type="note" title="Looking for Ahoy v2?">
  Homebrew has switched to v3, so `brew install ahoy` now installs the latest v3 release. The Linux
  command above resolves to v3 as well, since it downloads from `/releases/latest/`.

  v3 is intended to be fully backwards compatible with existing v2 `.ahoy.yml` files, so most
  projects need no changes. If you do still need v2, download it from the
  [v2.5.0 release page](https://github.com/ahoy-cli/ahoy/releases/tag/v2.5.0) - v2.5.0 is the latest
  v2 release, and there is no `ahoy@2` Homebrew formula.

  ```bash
  # Linux amd64. The v2 release also provides ahoy-bin-linux-arm64, ahoy-bin-linux-arm,
  # ahoy-bin-darwin-amd64 and ahoy-bin-darwin-arm64.
  sudo wget -q https://github.com/ahoy-cli/ahoy/releases/download/v2.5.0/ahoy-bin-linux-amd64 -O /usr/local/bin/ahoy && sudo chown $USER /usr/local/bin/ahoy && chmod +x /usr/local/bin/ahoy
  ```
</Aside>

For security's sake, please [verify your download](#verifying-your-download).

Then verify that `ahoy` is working:

```bash
ahoy --version
```

## Start with examples

The quickest way to get going is to initialise a project with our curated examples file. It includes 20+ ready-to-use commands for common development workflows.

```bash
cd my-project
ahoy config init
```

This creates an `.ahoy.yml` in the current directory. Run `ahoy` on its own to see what's available:

```bash
ahoy
```

<Aside type="tip">
  Want to inspect the file before downloading? The examples file is at
  [`examples/examples.ahoy.yml`](https://github.com/ahoy-cli/ahoy/blob/master/examples/examples.ahoy.yml)
  in the repository.
</Aside>

## Write your own commands

Create an `.ahoy.yml` file in your project root:

```yaml
ahoyapi: v2

commands:
  hello:
    usage: Say hello to someone
    cmd: echo "Hello, $1!"

  start:
    usage: Start the dev environment
    cmd: docker-compose up -d

  logs:
    usage: Follow container logs
    cmd: docker-compose logs -f "$@"
```

Run your commands from anywhere in the project tree:

```bash
ahoy hello World   # Hello, World!
ahoy start
ahoy logs web
ahoy              # Shows all commands and their usage text
```

<Aside type="note">
  Ahoy searches up the directory tree for `.ahoy.yml`, so you can run commands from any subdirectory
  in your project.
</Aside>

## Verifying your download

Homebrew checks each download against the SHA-256 in its formula, so there's nothing extra to do if you used `brew install`. If you install the binary yourself, download it, check it, then install the file you checked.

Each release includes an `ahoy_<version>_checksums.txt` file with a SHA-256 checksum for every file in the release. From v3.0.2, that file is also signed with [cosign](https://docs.sigstore.dev/). Set `FILE` to the binary for your platform, such as `ahoy-bin-darwin-arm64` on an Apple Silicon Mac:

```bash
VERSION=3.0.2
FILE=ahoy-bin-linux-amd64
BASE=https://github.com/ahoy-cli/ahoy/releases/download/v$VERSION

curl -fsSLO $BASE/$FILE
curl -fsSLO $BASE/ahoy_${VERSION}_checksums.txt
curl -fsSLO $BASE/ahoy_${VERSION}_checksums.txt.bundle

cosign verify-blob ahoy_${VERSION}_checksums.txt \
  --bundle ahoy_${VERSION}_checksums.txt.bundle \
  --certificate-identity "https://github.com/ahoy-cli/ahoy/.github/workflows/release.yml@refs/tags/v${VERSION}" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  && sha256sum -c ahoy_${VERSION}_checksums.txt --ignore-missing \
  && sudo install -m 755 $FILE /usr/local/bin/ahoy
```

Each step only runs if the one before it passed:

1. `cosign` checks that Ahoy's own release workflow made the checksums file, for the version you asked for. A signature from any other tag or branch fails.
2. `sha256sum` checks your binary against that checksums file. `--ignore-missing` checks only the files you downloaded.
3. `install` puts that same binary in `/usr/local/bin`.

On macOS, use `shasum -a 256 -c` instead of `sha256sum -c`.

There's no public key to download, because cosign signing here is keyless: the signature records which workflow and tag made it. The signature matters because a checksum shows a file is intact, but not who made it. Someone who could replace the binary could replace the checksums file too.

<Aside type="caution" title="cosign v3">
  cosign v3 replaced the `--output-signature` and `--output-certificate` flags with `--bundle`, so
  examples written for cosign v2 won't work.
</Aside>

### Releases before v3.0.2

v3.0.1 has checksums but no signature, so you can only do the checksum step:

```bash
VERSION=3.0.1
FILE=ahoy-bin-linux-amd64
BASE=https://github.com/ahoy-cli/ahoy/releases/download/v$VERSION

curl -fsSLO $BASE/$FILE
curl -fsSLO $BASE/ahoy_${VERSION}_checksums.txt

sha256sum -c ahoy_${VERSION}_checksums.txt --ignore-missing \
  && sudo install -m 755 $FILE /usr/local/bin/ahoy
```

In v3.0.0 and earlier, the checksums file only lists the `.tar.gz` and `.zip` archives and SBOMs, so you can't check the `ahoy-bin-*` binary on its own.
