When your `.ahoy.yml` gets long, you can move groups of commands into other files with `imports`.

## Importing a file

Give a command `imports` instead of `cmd`, and the commands in those files become its subcommands:

```yaml
# .ahoy.yml
ahoyapi: v2

commands:
  db:
    usage: Database commands
    imports:
      - ./.ahoy/db.ahoy.yml
```

```yaml
# .ahoy/db.ahoy.yml
ahoyapi: v2

commands:
  backup:
    usage: Back up the database
    cmd: mysqldump -u$DB_USER -p$DB_PASS $DB_NAME > backup.sql

  restore:
    usage: Restore from a backup file
    cmd: mysql -u$DB_USER -p$DB_PASS $DB_NAME < $1
```

Now you have `ahoy db backup` and `ahoy db restore`.

Every imported file needs its own `ahoyapi: v2` line.

<Aside type="note">
  Import paths are relative to the file that contains them, not to the folder you're in.
</Aside>

## Optional imports <Badge text="v2.2.0+" variant="tip" />

Normally Ahoy stops with an error if an imported file is missing. Add `optional: true` and Ahoy skips the command quietly instead. This suits personal or team-only commands that not everyone has:

```yaml
ahoyapi: v2

commands:
  local:
    usage: Local development extras
    optional: true
    imports:
      - ./local.ahoy.yml
```

If `local.ahoy.yml` doesn't exist, `ahoy local` just doesn't appear in the list.

## Overriding commands

When two commands have the same name, the last one defined wins:

```yaml
# .ahoy/base.ahoy.yml
ahoyapi: v2

commands:
  test:
    usage: Run tests
    cmd: npm test
```

```yaml
# .ahoy.yml
ahoyapi: v2

commands:
  shared:
    imports:
      - ./.ahoy/base.ahoy.yml

  test:
    usage: Run tests with coverage
    cmd: npm test -- --coverage
```

Here the `test` in `.ahoy.yml` replaces the imported one.

## A typical layout

Larger projects often keep one file per topic:

```
project/
├── .ahoy.yml
└── .ahoy/
    ├── db.ahoy.yml
    ├── docker.ahoy.yml
    └── deploy.ahoy.yml
```

```yaml
# .ahoy.yml
ahoyapi: v2

commands:
  db:
    usage: Database commands
    imports:
      - ./.ahoy/db.ahoy.yml

  docker:
    usage: Container commands
    imports:
      - ./.ahoy/docker.ahoy.yml

  deploy:
    usage: Deployment commands
    imports:
      - ./.ahoy/deploy.ahoy.yml
```

## Sharing commands between projects

Import paths can point outside the project, so several projects can share one set of commands:

```yaml
commands:
  shared:
    imports:
      - ../../shared-ahoy/docker.ahoy.yml
```
