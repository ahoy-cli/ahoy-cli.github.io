An Ahoy command is a shell command with a name and some help text, written in YAML.

## A minimal command

A command needs a name and a `cmd`. Everything else is optional, but a `usage` line is worth adding:

```yaml
ahoyapi: v2

commands:
  hello:
    usage: Say hello to someone
    cmd: echo "Hello, $1!"
```

The `usage` line is what people see when they run `ahoy`, so keep it short and clear.

## Arguments

Arguments arrive as normal bash positional parameters. Use `$1`, `$2` and so on for specific ones, or `"$@"` to pass them all through:

```yaml
commands:
  shell:
    usage: Open a shell in a container
    cmd: docker compose exec $1 bash

  run:
    usage: Run any command in the app container
    cmd: docker compose exec app "$@"
```

```bash
ahoy shell web
ahoy run npm test --watch
ahoy run chown -R www-data:www-data .
```

Flags count as arguments. Everything you type after the command name reaches your command as typed, in the same order. [Command execution](/guides/command-execution#arguments) has the details, including how `--` is handled.

## Multi-line scripts

For anything longer than one line, use a YAML block (`|`). It's normal bash inside:

```yaml
commands:
  setup:
    usage: Set up the project from scratch
    cmd: |
      echo "Installing dependencies..."
      npm install

      echo "Running migrations..."
      ./migrate.sh

      echo "All done. Run 'ahoy start' to begin."
```

## Longer help text <Badge text="v3" variant="success" />

`usage` is the one line shown in the list. `description` is longer help, shown when someone runs `ahoy help <command>`:

```yaml
commands:
  deploy:
    usage: Deploy the application
    description: |
      Deploys to the given environment, running tests and building
      assets first. Needs .env.deploy to be set up.

      Usage:
        ahoy deploy staging
        ahoy deploy production

      The production deploy asks for confirmation unless CI=true
      is set.
    cmd: ./scripts/deploy.sh $1
```

## Aliases <Badge text="v2.2.0+" variant="tip" />

Aliases are short names for a command. They're listed next to the main name:

```yaml
commands:
  start-dev:
    usage: Start the development environment
    aliases: ["up", "start"]
    cmd: docker compose up -d

  open-shell:
    usage: Open a shell in the app container
    aliases: ["shell", "sh", "bash"]
    cmd: docker compose exec app bash
```

Give the command a descriptive name, and add short aliases for the ones you type all day.

## Calling other commands

A command can run other Ahoy commands:

```yaml
commands:
  ci:
    usage: Run the full CI pipeline locally
    cmd: |
      ahoy lint
      ahoy test
      ahoy build

  fresh:
    usage: Tear down and rebuild everything
    cmd: |
      ahoy down
      docker compose build --no-cache
      ahoy up
      ahoy install
```

## Asking before destructive commands

For commands that can't be undone, add a `confirm` helper that asks first. The [examples file](https://github.com/ahoy-cli/ahoy/blob/master/examples/examples.ahoy.yml) has one that also works in scripts and CI, where you answer in advance with `AHOY_CONFIRM_RESPONSE=y`:

```yaml
commands:
  db:reset:
    usage: Reset the database to a clean state
    cmd: |
      ahoy confirm "This will destroy all database data. Continue?" || exit 0
      docker compose exec db mysql -u"$DB_USER" -p"$DB_PASS" -e \
        "DROP DATABASE IF EXISTS \`$DB_NAME\`; CREATE DATABASE \`$DB_NAME\`;"
      echo "Database reset."

  confirm:
    hide: true
    cmd: |
      if [ -z "${AHOY_CONFIRM_RESPONSE}" ]; then
        read -r -p ">> $1 [y/N] " AHOY_CONFIRM_RESPONSE
        RESPONSE_LOWER=$(printf '%s' "${AHOY_CONFIRM_RESPONSE}" | tr '[:upper:]' '[:lower:]')
        if [ "$RESPONSE_LOWER" != "y" ] && [ "$RESPONSE_LOWER" != "yes" ]; then
          echo "Cancelled."
          exit 1
        fi
      else
        echo ">> $1 [y/N] ${AHOY_CONFIRM_RESPONSE}"
        [ "${AHOY_CONFIRM_WAIT_SKIP}" != "1" ] && sleep 3
      fi
```

`hide: true` keeps a helper out of the command list. You can still run it.

## Wrapping other tools

Ahoy works well for wrapping long container commands:

```yaml
commands:
  drush:
    usage: Run Drush in the CLI container
    cmd: docker compose exec cli drush --root=/var/www/html/web "$@"

  composer:
    usage: Run Composer in the CLI container
    cmd: docker compose exec cli composer "$@"

  node:
    usage: Run Node.js commands in the app container
    cmd: docker compose exec app node "$@"
```

Now the team can run `ahoy drush cache:rebuild` or `ahoy composer require vendor/package`. The wrapped tool gets all its own flags, even ones Ahoy also uses:

```bash
ahoy drush --help                     # Drush's help
ahoy composer require --dev vendor/pkg
ahoy drush sql:query --extra=-A "SELECT 1"
ahoy node --version
```

Because `--help` goes to the wrapped tool, use `ahoy help drush` to see Ahoy's help for the command.

<Aside type="caution" title="Fixed in v3.0.1">
  Ahoy v3.0.0 dropped any flag it didn't recognise, along with the word after it, without telling
  you. So `ahoy fix-perms chown -R www-data:www-data .` ran as `chown .`. Upgrade if you wrap
  anything that takes flags. See [issue #182](https://github.com/ahoy-cli/ahoy/issues/182).
</Aside>

## Commands with their own env file <Badge text="v2.3.0+" variant="tip" />

Use `env` to load settings for one command:

```yaml
commands:
  deploy:
    usage: Deploy to staging
    env: .env.deploy
    cmd: |
      echo "Deploying to $DEPLOY_HOST..."
      rsync -avz ./dist/ $DEPLOY_HOST:$DEPLOY_PATH
```

The [Environment variables guide](/guides/environment) covers env files in full.

## Example files

The repository has example files you can copy:

- [examples.ahoy.yml](https://github.com/ahoy-cli/ahoy/blob/master/examples/examples.ahoy.yml): around 30 commands for Docker, databases, testing, Drupal and deployment. `ahoy config init` downloads it, and it uses nearly every Ahoy feature, so it's a good file to read.
- [docker.ahoy.yml](https://github.com/ahoy-cli/ahoy/blob/master/examples/docker.ahoy.yml): Docker Compose commands to import into your own config.
- [confirmation.ahoy.yml](https://github.com/ahoy-cli/ahoy/blob/master/examples/confirmation.ahoy.yml): the confirmation helper on its own, ready to import.

Every field is listed in the [YAML schema](/reference/yaml-schema).
