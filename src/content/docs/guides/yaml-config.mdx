# YAML Configuration Guide

Ahoy's power comes from its simple, flexible YAML configuration. This practical guide will help you create effective `.ahoy.yml` files for your projects with step-by-step examples and common patterns.

## Getting Started

Let's walk through creating your first `.ahoy.yml` file from scratch:

### 1. Create a Basic Configuration

Start by creating a file named `.ahoy.yml` in your project root:

```yaml
ahoyapi: v2

commands:
  hello:
    usage: Say hello to the world
    cmd: echo "Hello, World!"
```

That's it! Run `ahoy hello` and you'll see the message printed.

### 2. Add More Commands

Let's add a few more practical commands:

```yaml
ahoyapi: v2

commands:
  hello:
    usage: Say hello to the world
    cmd: echo "Hello, World!"
  
  list:
    usage: List files in the current directory
    cmd: ls -la
  
  info:
    usage: Show system information
    cmd: |
      echo "User: $(whoami)"
      echo "Directory: $(pwd)"
      echo "Date: $(date)"
```

### 3. Try Using Arguments

Commands can accept arguments just like shell scripts:

```yaml
ahoyapi: v2

commands:
  hello:
    usage: Say hello to someone (or world if no name provided)
    cmd: |
      NAME="${1:-World}"
      echo "Hello, $NAME!"
```

Try it with: `ahoy hello Drew` or just `ahoy hello`

## Common Use Cases

### Web Development Workflow

Here's a practical example for a web development project:

```yaml
ahoyapi: v2

commands:
  start:
    usage: Start the development server
    cmd: npm run start
    
  build:
    usage: Build the production assets
    cmd: npm run build
    
  test:
    usage: Run the test suite
    cmd: npm test
    
  lint:
    usage: Lint the codebase
    cmd: |
      echo "Linting JavaScript..."
      npm run lint:js
      echo "Linting CSS..."
      npm run lint:css
```

### Database Operations

For projects with database needs:

```yaml
ahoyapi: v2
env: .env

commands:
  db-backup:
    usage: Backup the database
    cmd: |
      TIMESTAMP=$(date +%Y%m%d_%H%M%S)
      mysqldump -u$DB_USER -p$DB_PASS $DB_NAME > backup_$TIMESTAMP.sql
      echo "Database backed up to backup_$TIMESTAMP.sql"
  
  db-restore:
    usage: Restore database from a backup file
    cmd: |
      if [ -z "$1" ]; then
        echo "Please provide a backup file: ahoy db-restore backup_file.sql"
        exit 1
      fi
      
      mysql -u$DB_USER -p$DB_PASS $DB_NAME < $1
      echo "Database restored from $1"
```

### Docker-Based Development

For Docker-based projects:

```yaml
ahoyapi: v2

commands:
  up:
    usage: Start all containers
    cmd: docker-compose up -d
  
  down:
    usage: Stop all containers
    cmd: docker-compose down
  
  logs:
    usage: View logs from containers
    cmd: docker-compose logs -f $@
  
  shell:
    usage: Open a shell in a container
    cmd: |
      if [ -z "$1" ]; then
        echo "Please specify a service: ahoy shell web"
        exit 1
      fi
      docker-compose exec $1 bash
```

## Creating a Command Toolkit

Let's build a more comprehensive setup by organizing commands into logical groups:

### Step 1: Create the main `.ahoy.yml` file

```yaml
ahoyapi: v2
env: .env

usage: Project development commands

commands:
  # Command groups
  dev:
    usage: Development commands
    imports:
      - ./.ahoy/dev.yml
  
  db:
    usage: Database commands
    imports:
      - ./.ahoy/db.yml
  
  deploy:
    usage: Deployment commands
    imports:
      - ./.ahoy/deploy.yml
  
  # Quick commands
  start:
    usage: Start the development environment
    cmd: ahoy dev up
  
  stop:
    usage: Stop the development environment
    cmd: ahoy dev down
```

### Step 2: Create a directory for command files

```
mkdir -p .ahoy
```

### Step 3: Create development commands in `.ahoy/dev.yml`

```yaml
ahoyapi: v2

commands:
  up:
    usage: Start development servers
    cmd: docker-compose up -d
  
  down:
    usage: Stop development servers
    cmd: docker-compose down
  
  restart:
    usage: Restart development servers
    cmd: |
      ahoy dev down
      ahoy dev up
  
  logs:
    usage: Follow container logs
    cmd: docker-compose logs -f
```

### Step 4: Create database commands in `.ahoy/db.yml`

```yaml
ahoyapi: v2
env: .env.db

commands:
  backup:
    usage: Backup the database
    cmd: |
      TIMESTAMP=$(date +%Y%m%d_%H%M%S)
      docker-compose exec database mysqldump -u$DB_USER -p$DB_PASS $DB_NAME > backups/backup_$TIMESTAMP.sql
      echo "Database backed up to backups/backup_$TIMESTAMP.sql"
  
  restore:
    usage: Restore database from a backup file
    cmd: |
      if [ -z "$1" ]; then
        echo "Please provide a backup file: ahoy db restore backups/backup_file.sql"
        exit 1
      fi
      
      cat $1 | docker-compose exec -T database mysql -u$DB_USER -p$DB_PASS $DB_NAME
      echo "Database restored from $1"
```

## Advanced Techniques

### Using Environment Variables Effectively

Create a `.env` file for global configuration:

```
# Database credentials
DB_USER=admin
DB_PASS=secret
DB_NAME=myproject

# Project settings
PROJECT_NAME=awesome-app
NODE_ENV=development
```

Then reference these in your commands:

```yaml
ahoyapi: v2
env: .env

commands:
  status:
    usage: Show project status
    cmd: |
      echo "Project: $PROJECT_NAME"
      echo "Environment: $NODE_ENV"
      echo "Database: $DB_NAME (User: $DB_USER)"
```

### Using Different Runtime Environments

For different environments, create environment-specific command files:

`.ahoy/staging.yml`:
```yaml
ahoyapi: v2
env: .env.staging

commands:
  deploy:
    usage: Deploy to staging
    cmd: |
      echo "Deploying to staging..."
      rsync -avz --delete ./dist/ $STAGING_SERVER:$STAGING_PATH
      ssh $STAGING_SERVER "$STAGING_RESTART_CMD"
```

`.ahoy/production.yml`:
```yaml
ahoyapi: v2
env: .env.production

commands:
  deploy:
    usage: Deploy to production
    cmd: |
      echo "Deploying to production..."
      # Add confirmation prompt for safety
      read -p "Are you sure you want to deploy to PRODUCTION? (y/n) " -n 1 -r
      echo
      if [[ ! $REPLY =~ ^[Yy]$ ]]; then
        echo "Deployment canceled"
        exit 1
      fi
      
      rsync -avz --delete ./dist/ $PROD_SERVER:$PROD_PATH
      ssh $PROD_SERVER "$PROD_RESTART_CMD"
```

Main `.ahoy.yml`:
```yaml
ahoyapi: v2

commands:
  staging:
    usage: Staging environment commands
    imports:
      - ./.ahoy/staging.yml
      
  production:
    usage: Production environment commands
    imports:
      - ./.ahoy/production.yml
```

### Building Complex Command Sequences

```yaml
ahoyapi: v2

commands:
  release:
    usage: Prepare and deploy a new release
    cmd: |
      # Ensure we're on the main branch
      git checkout main
      
      # Get the version from the user
      read -p "Enter release version (e.g., 1.2.3): " VERSION
      
      # Validate version format
      if [[ ! $VERSION =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]]; then
        echo "Error: Version must follow semantic versioning (e.g., 1.2.3)"
        exit 1
      fi
      
      # Run tests
      echo "Running tests..."
      ahoy test
      if [ $? -ne 0 ]; then
        echo "Tests failed! Release aborted."
        exit 1
      fi
      
      # Build the application
      echo "Building application..."
      ahoy build
      
      # Create a release tag
      echo "Creating release tag v$VERSION..."
      git tag -a "v$VERSION" -m "Release version $VERSION"
      
      # Push to origin
      echo "Pushing to remote repository..."
      git push origin main
      git push origin "v$VERSION"
      
      # Deploy the application
      echo "Deploying to production..."
      ahoy production deploy
      
      echo "Release v$VERSION complete!"
```

## Command Aliases and Shortcuts

Aliases make frequently used commands more accessible. Here's how to create and use them effectively:

### Creating Command Aliases

```yaml
ahoyapi: v2

commands:
  # Long form commands
  start-development-server:
    usage: Start the development server
    cmd: docker-compose up -d web db

  run-test-suite:
    usage: Run the complete test suite
    cmd: npm test
    
  # Aliases for common commands
  s:
    usage: Alias for start-development-server
    cmd: ahoy start-development-server
    
  t:
    usage: Alias for run-test-suite
    cmd: ahoy run-test-suite
```

### Function-Style Aliases

For commands that take arguments, create function-style aliases:

```yaml
ahoyapi: v2

commands:
  # Main command with arguments
  db-query:
    usage: Run a SQL query against the database
    cmd: |
      docker-compose exec db mysql -u$DB_USER -p$DB_PASS $DB_NAME -e "$@"

  # Shorthand alias
  q:
    usage: Shorthand for db-query
    cmd: ahoy db-query "$@"
```

Use it like: `ahoy q "SELECT * FROM users LIMIT 5;"`

### Common Shortcuts Pattern

Here's a practical pattern for frequently used command combinations:

```yaml
ahoyapi: v2

commands:
  # Create a quick restart command
  restart:
    usage: Quickly restart the development environment
    cmd: |
      echo "Restarting development environment..."
      ahoy down
      ahoy up
      
  # Quick status check
  status:
    usage: Check project status
    cmd: |
      echo "=== Container Status ==="
      docker-compose ps
      echo "=== Git Status ==="
      git status -s
      echo "=== Branch Info ==="
      git branch -v
```

## Troubleshooting Tips

### Common Issues and Solutions

#### Problem: Ahoy Commands Not Found

If your ahoy commands aren't being recognized:

```yaml
ahoyapi: v2

commands:
  doctor:
    usage: Check configuration and diagnose common issues
    cmd: |
      echo "Checking ahoy configuration..."
      
      # Check if .ahoy.yml exists
      if [ ! -f ".ahoy.yml" ]; then
        echo "ERROR: .ahoy.yml not found in current directory"
        echo "Make sure you're in the project root directory"
        exit 1
      fi
      
      # Check ahoy version
      AHOY_VERSION=$(ahoy --version)
      echo "Ahoy version: $AHOY_VERSION"
      
      # Check for required tools
      echo "Checking dependencies..."
      command -v docker >/dev/null 2>&1 || { echo "Docker not found"; }
      command -v docker-compose >/dev/null 2>&1 || { echo "Docker Compose not found"; }
      
      echo "Checks complete!"
```

#### Problem: Environment Variables Not Loading

If your environment variables aren't being loaded correctly:

```yaml
ahoyapi: v2
env: .env

commands:
  env-test:
    usage: Test if environment variables are loading properly
    cmd: |
      echo "Testing environment variables..."
      
      # Check important variables
      [ -z "$DB_NAME" ] && echo "WARNING: DB_NAME is not set"
      [ -z "$API_KEY" ] && echo "WARNING: API_KEY is not set"
      
      # Show loaded variables (omit secrets)
      echo "PROJECT_NAME: $PROJECT_NAME"
      echo "ENVIRONMENT: $ENVIRONMENT"
      
      # Check .env file
      if [ ! -f ".env" ]; then
        echo "ERROR: .env file doesn't exist!"
        echo "Create it from .env.example with your settings"
      fi
```

#### Problem: Import Files Not Loading

If your imported command files aren't working:

```yaml
ahoyapi: v2

commands:
  import-check:
    usage: Check if import files are correctly structured
    cmd: |
      echo "Checking import files..."
      
      # Check important import files
      for file in .ahoy/*.yml; do
        echo "Checking $file..."
        if grep -q "ahoyapi: v2" "$file"; then
          echo "✓ $file has correct API version"
        else
          echo "✗ $file is missing API version declaration"
        fi
      done
```

## Best Practices

### Structuring Your Commands

1. **Group Related Commands**:

```yaml
ahoyapi: v2

commands:
  # Frontend development group
  frontend:
    usage: Frontend development commands
    imports:
      - .ahoy/frontend.yml
      
  # Backend development group  
  backend:
    usage: Backend development commands
    imports:
      - .ahoy/backend.yml
```

2. **Document with Helpful Usage Messages**:

```yaml
ahoyapi: v2

commands:
  deploy:
    usage: |
      Deploy to an environment
      
      Examples:
        ahoy deploy staging
        ahoy deploy production
        
      Options:
        --skip-tests  Skip the test suite
    cmd: |
      # Command implementation...
```

3. **Use Consistent Naming Conventions**:

```yaml
ahoyapi: v2

commands:
  # Use verb-noun format
  build-app:
    usage: Build the application
    cmd: npm run build
    
  run-tests:
    usage: Run the test suite
    cmd: npm test
    
  deploy-staging:
    usage: Deploy to staging
    cmd: # ...
```

4. **Provide Feedback and Progress**:

```yaml
ahoyapi: v2

commands:
  setup:
    usage: Set up the development environment
    cmd: |
      echo "=== Starting setup process ==="
      
      echo "[1/4] Checking dependencies..."
      # dependency checks
      
      echo "[2/4] Pulling containers..."
      docker-compose pull
      
      echo "[3/4] Building application..."
      npm install
      
      echo "[4/4] Setting up database..."
      ahoy db setup
      
      echo "=== Setup complete! ==="
      echo "Run 'ahoy start' to begin development"
```

5. **Handle Errors Gracefully**:

```yaml
ahoyapi: v2

commands:
  deploy:
    usage: Deploy the application
    cmd: |
      # Set error handling
      set -e
      trap 'echo "Deployment failed! See errors above."' ERR
      
      # Command steps...
      
      # If we get here, it succeeded
      echo "✅ Deployment completed successfully!"
```
