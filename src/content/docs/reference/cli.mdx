# Ahoy CLI Reference

This guide provides a complete reference for all Ahoy command-line interface options and features.

## Command Syntax

The basic syntax for Ahoy commands is:

```bash
ahoy [options] [command] [args...]
```

## Global Options

### Basic Options

```bash
--file, -f        # Specify an alternate YAML file
--help, -h        # Show help
--verbose         # Enable verbose output
--version         # Show version information
```

### Special Options

```bash
--generate-bash-completion  # Generate bash completion script
```

## Command Types

### Built-in Commands

These commands are available by default:

```bash
ahoy help         # Show help about a command
ahoy version      # Show version information
```

### Custom Commands

Custom commands are defined in your `.ahoy.yml` file and are run as:

```bash
ahoy command-name [arguments]
```

For subcommands:

```bash
ahoy namespace command-name [arguments]
```

## Configuration Files

### Default Location

Ahoy looks for configuration files in this order:
1. File specified by `--file` flag
2. `.ahoy.yml` in current directory
3. `.ahoy.yml` in parent directories

### File Format

```yaml
ahoyapi: v2

# Optional global environment file
env: .env

# Optional command entrypoint override
entrypoint:
  - bash
  - "-c"
  - '{{cmd}}'
  - '{{name}}'

# Commands
commands:
  command-name:
    usage: Command description
    cmd: command to execute
```

## Command Arguments

Arguments are passed to commands as bash-style positional parameters:

- `$1`, `$2`, etc.: Individual arguments
- `$@`: All arguments
- `$0`: Command name

Example:
```yaml
commands:
  greet:
    usage: Greet someone
    cmd: echo "Hello, $1!"
```

Usage:
```bash
ahoy greet World  # Output: Hello, World!
```

## Environment Variables

### Environment Files

```yaml
# Global environment file
env: .env

commands:
  command:
    # Command-specific environment file
    env: .env.local
```

### Variable Access

Environment variables can be accessed in commands:

```yaml
commands:
  db:
    cmd: mysql -u$DB_USER -p$DB_PASS $DB_NAME
```

## Exit Codes

Ahoy uses standard Unix exit codes:

- `0`: Success
- `1`: General error
- `2`: Misuse of shell builtins
- Other codes: Command-specific error codes

## Command Resolution

When resolving commands, Ahoy:

1. Searches for `.ahoy.yml` from current directory up
2. Processes any imports
3. Applies "last in wins" for duplicate commands
4. Executes the matching command

## Shell Completion

### Bash Completion

Enable bash completion:

```bash
eval "$(ahoy --generate-bash-completion)"
```

### Zsh Completion

Use the dedicated Zsh plugin:

1. Install [ahoy-cli/zsh-ahoy](https://github.com/ahoy-cli/zsh-ahoy)
2. Configure in your `.zshrc`

## Advanced Usage

### Using Different Interpreters

Override the default bash interpreter:

```yaml
# Python
entrypoint:
  - python3
  - "-c"
  - '{{cmd}}'

# Node.js
entrypoint:
  - node
  - "-e"
  - '{{cmd}}'
```

### Working with Docker

Special considerations for Docker commands:

```yaml
commands:
  # Direct container execution
  exec:
    cmd: docker-compose exec $1 ${@:2}

  # Piping input
  import:
    cmd: docker exec -i container mysql < $1
```

## Examples

### Basic Command
```yaml
commands:
  hello:
    usage: Say hello
    cmd: echo "Hello!"
```

### Command with Arguments
```yaml
commands:
  greet:
    usage: Greet someone
    cmd: echo "Hello, $1!"
```

### Subcommands
```yaml
commands:
  dev:
    usage: Development commands
    imports:
      - dev.ahoy.yml
```

### Environment-Specific Command
```yaml
commands:
  deploy:
    usage: Deploy to environment
    env: .env.deploy
    cmd: ./deploy.sh $1
```

## Best Practices

1. **Use Descriptive Names**
   ```yaml
   # ✅ Good
   commands:
     db-migrate:
       cmd: ./migrate.sh
   
   # ❌ Bad
   commands:
     m:
       cmd: ./migrate.sh
   ```

2. **Document Command Usage**
   ```yaml
   commands:
     deploy:
       usage: |
         Deploy to specified environment
         Args:
           $1: Environment name (dev|staging|prod)
   ```

3. **Use Environment Variables**
   ```yaml
   commands:
     db:
       env: .env.db
       cmd: mysql -u$DB_USER -p$DB_PASS
   ```

4. **Organize Related Commands**
   ```yaml
   commands:
     db:
       imports:
         - ./commands/db.ahoy.yml
   ```

## Troubleshooting

### Common Issues

1. **Command Not Found**
   - Check `.ahoy.yml` location
   - Verify command name
   - Check import paths

2. **Environment Variables Not Set**
   - Verify env file exists
   - Check file permissions
   - Use `--verbose` to debug

3. **Import Issues**
   - Use relative paths
   - Check file existence
   - Verify YAML syntax

### Debug Mode

Run with verbose output:

```bash
ahoy --verbose command
```

This shows:
- Command resolution
- Environment loading
- Execution details
